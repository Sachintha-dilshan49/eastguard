# Spec §10 coverage

Every row of the spec §10 scenario table, with the tests that cover it and the result of the final run
(`java -ea -cp out eastguard.test.AllTests`: **357 passed, 0 failed** (97 s, test PKI already generated), on the machine described in
[`RESULTS.md`](RESULTS.md)). Test names are `Class.method` in `test/eastguard/test/`. "Demo" points to the runnable
demos (`src/eastguard/demos/`) that show the same behaviour with real processes or sockets; their checks are
printed as `[ok]`/`[FAIL]` and they exit non-zero on any failure.

The suite separates the kinds of test §10 asks for:

| Kind | Where |
|------|-------|
| Pure unit tests (deterministic `Clock`, no I/O) | `PolicyEvaluatorTest`, `RiskEngineTest`, codec tests (`LeaseCodecTest`, `HandshakeCodecTest`, `TelemetryCodecTest`, `NoticeCodecTest`, `WireTest`), `DomainTest`, `CidrTest`, `CryptoTest`, `SessionIndexTest`, `StateSyncTest`, `ControlPlaneImplTest`, `LearningFreezeTest`, `DashboardControllerTest` (fake EDT and settable monotonic clock) |
| Local integration tests (real sockets on ephemeral loopback ports, owned test services) | `TlsTest`, `TokenServerTest`, `GatewayTest`, `JournalTest`, `RmiTest`, `ControlE2ETest`, `TelemetryVerifierTest`, `TelemetryProducerTest`, `DetectorPipelineTest`, `AuditHttpTest`, `CredentialsTest`, `IsolationTest` |
| Real multicast qualification | `QuarantineBusTest.testRealMulticastLoopbackQualification` (prints SKIP, not FAIL, on a host without local multicast), `DemoM4_Multicast` |
| Load / measurement runs | `DemoM1_Nio 1000`, `DemoM4_Multicast`, `DemoFinal --measure 20` (separate JVMs); numbers in `RESULTS.md` |

## What cannot be tested locally, and what was done instead

| Scenario | Why not locally | Done instead |
|----------|-----------------|--------------|
| 16 Deployment isolation | It is a property of the deployment: separate hosts or network namespaces, host firewall rules, segmentation between workloads and backends. On one Windows host every process shares the loopback interface, so any local process can open `127.0.0.1:7002`. | Bound the backend fixture to loopback and tested that it refuses every other local address; checked that no configured component listens on or sends to a backend port; checked structurally that a client cannot choose the gateway's destination. For a real deployment: backend listens only on an address the gateway host can reach, a host firewall drops every other source, then a probe from a workload host to the backend must fail while the same flow through the gateway works. |
| Cross-host multicast (rows 9–10 on a real segment) | One machine; no switch, no IGMP snooping, no second NIC. | Loss, duplication, delay and reordering through `MemoryTransport` and `FaultyTransport`; real multicast on loopback (`testRealMulticastLoopbackQualification`, `DemoM4_Multicast`); real multicast between **separate JVM processes** on this host in `DemoFinal` (one control-plane sender, two gateways and the token service as receivers). Qualification on the deployment segment remains to be done (DEVIATIONS 8.8). |
| 13 Disk full | Filling a real volume in a test is destructive and slow. | `JournalTest.testFailedWriteFencesFurtherAppends` makes the next write fail the way a dead or full disk does (closed channel → `IOException`); `ControlPlaneImplTest.testJournalFailureFencesMutationsAndSync` shows the mutation returns no success and readiness fails. An actual `ENOSPC` was not induced. |
| 13 Process crash | A unit test cannot kill its own JVM. | Torn writes are tested at every byte offset of the last frame. By hand on this machine (RESULTS "Operational checks"): gateway `app-03` was force-killed while `run-demo.ps1` ran, and the launcher stopped the other six cleanly; the launcher itself was force-killed and all JVMs exited within 4 s. A forced kill of the control plane followed by journal replay was **not** drilled separately; replay after a clean stop runs at the end of every `DemoM5_Rmi`. |
| 15 Swing pixels | No display in an automated run. | Controller, model and worker tested with a fake EDT thread and a settable clock; the views were rendered offscreen during development and the live console was smoke-checked by hand against a running control plane (DEVIATIONS 9.12). |
| 14 Control-key rotation, hitless telemetry-key rotation | Not implemented (no mutation to stage a new control key; one key ID per telemetry producer). | Recorded as simplifications (DEVIATIONS 8.1, 7.12). Untrusted and revoked control keys are rejected. |
| Release load test (1,000 sessions) on declared hardware | Only this laptop is available. | `DemoM1_Nio 1000` run on this laptop; numbers and limits in `RESULTS.md`. |
